# Retained review completion and evidence preservation

The retained Capital episode has three unresolved review requests and one
completed protocol diagnostic. A replacement key and a compatible response
parser do not settle those earlier requests. The explicit completion plan
preserves all eighteen historical records and the original production root,
then accounts for four prospective reviews: STORY, VISUAL, blind ASR and
PROSODY. Its stated aggregate is eight attempts, including the four already
occupied. The earlier six-attempt manifests and terminal guards stay intact.

`retained_review_completion_plan` provides one fixed, operator-commissioned
plan. Commissioning binds the archived credential, complete historical
snapshot, source/OAuth continuity, original audio metadata, bounded policy
window and operator evidence. Nine new permanent records contain the immutable
manifest and independently committed child journal heads. Partial records,
changed source, rollback or uncertain acknowledgements block continuation.
There is no automatic commissioning, reset, renewal or provider request here.

Both journals accept the exact closed `completion_plan` capability as an
alternative to the existing `successor` selection. Neither ordinary journal
commissioning nor unused-window reconfirmation can recreate selected records.
Each new reservation must follow the fixed global order and every previous
reservation must be acknowledged. Unknown outcomes remain occupied. Protocol
acknowledgement alone does not establish a positive critique; the existing
source-bound story, visual, transcription and prosody gates still apply.

The plan records the owner's USD 10 monthly additional-cash ceiling, leaves
historical extra cash unknown and permits zero new cash through this route.
The existing subscription and documented `route-llm` terms are the stated
entitlement basis. The plan does not query or verify account billing. It cannot
initialize the financial ledger, select a premium model or fall back to a
cash provider. A commissioning operator must reconcile the applicable
entitlement and execution bounds before sending requests.

## Capture before response validation

The two explicit runtime scopes require `capture_transport=True` for a
completion plan. Default calls keep their existing behavior. After the actual
journal reservation is acknowledged, the capture path writes and reads back
its own permanent intent before its single HTTP request. It then captures the
actual prepared body, outgoing body and bounded response before status or
schema validation. Non-success, malformed and explicitly partial responses
remain diagnostic evidence.

The full packet is encrypted under a separate application-key domain and
stored in a private, create-only object. Exact readback, private object ACL and
a permanent Redis anchor must be acknowledged before semantic observation.
Ambiguous storage results stop the scope and retain an issuer-bound encrypted
fallback for the original thread, including after scope closure. No response
headers containing credentials or arbitrary provider messages enter public
summaries. An abrupt process exit can still lose bytes before persistence;
captured diagnostics do not reconstruct or settle an earlier lost response.

## Exact retained cuts

`preserve_exact_cuts=True` prepares the six existing shots locally. It binds
original audio and clip bytes, package/source hashes, actual frame counts,
timeline order, executed normalization branches and arguments, and the
renderer and media-tool identities. The six resulting clips and their
derivation manifest are stored privately with create-only writes and exact
readback before the existing visual reviewer runs. Changed files or tool/code
identity reject reuse. The completion wrapper requires both cut preservation
and transport capture before entering its review scope.

These records identify newly prepared cut bytes; historical cut identity
remains unknown. The cut receipt alone grants no claim, final-render approval
or publication authority.

The opt-in visual path also records the actual thirty JPEG extractions from
those six cuts, including their ordered labels, probe and extraction arguments,
tool identities and exact image bytes. After the real VISUAL acknowledgement
and private review-artifact readback, a separate linkage record compares every
image and label with both the prepared request and actual outgoing body. Its
private manifest and permanent anchor are acknowledged under the same source
and selected-journal checks. Sampling or storage uncertainty stops this path;
neither a caller boolean nor existing JPEG files can supply this evidence.
This proves the recorded input linkage, while semantic acceptance and final
video QA remain separate requirements.

## Persisted audio and remaining delivery

The existing audio evidence consumer can select the closed completion plan.
It verifies both acknowledged components, private artifacts, original audio,
source continuity, all eighteen predecessors and current child/control heads
under one watched read. It does not send, observe a recreated response or renew
a request window. Passing audio components remain separate from story, exact
edit duration and final-render QA.

Production features remain subject to their existing deployment and funding
gates. Full story/visual and sampled-link evidence consumption, retained
rendering, final QA, private-first upload, public delivery and ordered
series continuation must be verified before claiming unattended operation.
