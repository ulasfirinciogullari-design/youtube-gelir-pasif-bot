# Explicit retained-review continuation after a credential replacement

The original Capital story and blind-ASR attempts retain their unresolved
reservations. Installing an accepted replacement key cannot erase those
attempts, rebind their policies, or turn their missing responses into reviews.
The existing owner authorization covers a separate, explicit included-only
continuation for the same retained source.

`retained_review_credential_successor.py` admits one fixed batch for the same
original root and leaf. It preserves all six legacy Redis records byte for
byte and counts their two occupied unknown attempts. The new batch permits at
most one story, one visual, one blind-ASR and one prosody request: at most six
attempts in total, including the old two. Neither an arbitrary namespace nor a
new nonce, child identity or repeated commissioning can add capacity.

The operator binds the exact predecessor snapshot, promoted encrypted
candidate archive, before/after credential bridge, successful read-only access
proof, promotion records and existing subscription assertion. The application
authenticates the archived replacement with its dedicated encryption domain
and checks it against the actual current server key. Hashes of operator files
record their provenance; they are not an account or billing lookup.

Both existing policy validators are reused. Source, voice, narration, package,
profile and OAuth bindings remain unchanged. Only the replacement credential,
subscription assertion and shared request window can change. The window lasts
at most 24 hours; historical additional cash remains unknown and the new cash
allowance stays zero. The model is exactly `route-llm`. The owner’s USD 10
monthly maximum is not converted into a fresh available balance.

Commissioning atomically stores the fixed control records and two selected
journals. Each later reservation still requires the existing runtime’s fresh
source and budget checks and one acknowledged transaction before its single
HTTP request. The control commitment tracks both child states with each
mutation, so rolling back only one child trio cannot clear an occupied slot.
Partial records, unknown replies, changed source or replaced credentials block
new requests. Legacy mutation paths are fenced once successor records exist;
legacy history remains readable. Coordinated rollback of every external copy
still requires external recovery.

`SuccessorAuthorization` is a private typed selection returned by commissioning
or watched readback. The two runtime scopes accept it explicitly; default
legacy behavior remains available before commissioning. The application does
not commission itself or automatically retry. The trusted retained operator
must enforce story acceptance before visual review and complete positive ASR
evidence before prosody, and stop its batch on rejection. The controller’s
capacity/unknown-outcome fence is not a semantic quality verdict.

The story/visual preparation persists actual acknowledged captures into the
selected journal’s artifact namespace. New audio evidence must likewise be
stored and consumed with the selected journal identity before it can be used
later. Neither the capability, journal observation, stored artifact nor shared
semantic report grants final-render, publication or next-video authority.
The retained renderer, final audio/video checks and publish/resume chain remain
separate integration work.
